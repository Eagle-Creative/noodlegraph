Block coding for any application

You bring the blocks: lamps, motors, sounds, orders, whatever your application does. Noodlegraph draws the graph, checks it and runs it.

This graph is running in your browser. Press Button, then change the graph: it runs as you edit.

Start

Noodlegraph is plain files: no install step, no build step, no dependencies. Copy two folders into your project and serve them.

FolderWhat it is
editors/web/The editor: noodlegraph.js, panzoom.js, noodlegraph.css
runtimes/javascript/src/The runtime that checks and runs graphs in a page or in Node.js
runtimes/python/The same runtime for Python 3.11 and later

A complete application is an editor, an engine and your blocks:

<link rel="stylesheet" href="editors/web/noodlegraph.css">
<div id="editor" style="height: 70vh"></div>
<script type="module">
  import { createEditor } from "./editors/web/noodlegraph.js";
  import { Context, Engine, STANDARD, catalogue, defineBlock, parse, registry }
    from "./runtimes/javascript/src/index.js";

  class Stage extends Context { lamp = "#000000"; }        // your application, as blocks see it

  const SetLamp = defineBlock({                            // a block of your own
    role: "action", kind: "set_lamp", title: "Set lamp",
    inputs: [{ name: "in", type: "flow" }, { name: "colour", type: "colour" }],
    fields: [{ name: "colour", kind: "colour", default: "#ff8800" }],
    run({ ctx, inputs }) { ctx.lamp = inputs.colour; return "out"; },
  });

  const blocks = registry(STANDARD, SetLamp);
  const engine = new Engine({ context: new Stage(), registry: blocks });
  const editor = createEditor(document.querySelector("#editor"), {
    blocks: catalogue(blocks),
    graph: { id: "hello", enabled: true, nodes: [], wires: [] },
    onChange: (graph) => engine.load([parse(graph)]),       // what is drawn is what runs
    onRun: (node) => engine.fire("hello", node),
  });
  await engine.load([parse(editor.getGraph())]);
  await engine.activate();
</script>

The folder demo/ is this with a name field, Save, an on and off switch, Import and Export.

How a graph works

A graph is blocks and the wires between them. People call the wires noodles.

White wires are the order of steps
A trigger block watches for something: a button, a time, a value. When it happens, the blocks wired after it run one after the other. That is a chain.
Coloured wires carry values
A value goes from a dot on the right of one block into a setting of another. Every setting that can take a wire has a dot of its type: number, yes or no, text, colour, or a list of those. Without a wire, the block uses what is typed into the setting.
Two white wires from one dot run at the same time
The chain goes on when both ways have finished. If one fails, the other stops.
If, For and While
If continues on one of two ways. For and While run the blocks on "each round" again and again, then continue on "done". For gives each round its number, i.
Variables remember
A variable is a named value of the graph. "Set number" stores, "Change number" counts, "Number variable" reads. Blocks that give the same name share the variable.
Graphs can run graphs
"Run graph" runs another graph from its "When run by another graph" block and waits for it. Build a sequence once, use it in several places.
Every chain runs on its own
Chains do not wait for each other. They run only while the engine is active; switching it off stops everything at once.

The graph is saved as one JSON document. What is drawn is exactly what runs:

{
  "schema": "noodlegraph/1",
  "id": "greet",
  "name": "Greet the audience",
  "enabled": true,
  "nodes": [
    { "id": "go",   "kind": "manual", "options": {},                  "position": [20, 40] },
    { "id": "wait", "kind": "wait",   "options": { "seconds": 0.4 }, "position": [280, 40] }
  ],
  "wires": [
    { "from_node": "go", "from_port": "out", "to_node": "wait", "to_port": "in" }
  ]
}

Your own blocks

A block type is a description, which the editor draws, and one function, which the engine runs. The function depends on the block's role.

RoleFunctionWhat it does
triggerstart({ ctx, options, emit }), returning how to stop. Or watch({ …, sleep }), an async function that runs until it is stopped.Calls emit() when its thing happens
actionrun({ ctx, options, inputs, sleep, variables })One step. Returns the name of the white dot to continue on
loopagain({ inputs, rounds }) and values({ inputs, rounds })Says whether another round runs, and what its dots give in it
valuecompute({ ctx, options, inputs, variables })Returns { dot: value }

A trigger

const ButtonPressed = defineBlock({
  role: "trigger", kind: "button", title: "When the button is pressed",
  start: ({ ctx, emit }) => ctx.onButton(() => emit()),   // what it returns stops it again
});

An action that takes a while

const MovePointer = defineBlock({
  role: "action", kind: "move_pointer", title: "Move pointer",
  inputs: [{ name: "in", type: "flow" }, { name: "angle", type: "number" }],
  fields: [{ name: "angle", kind: "float", min: 0, max: 180, default: 90 }],
  async run({ ctx, inputs, sleep }) {
    ctx.pointer = inputs.angle;
    await sleep(0.5);            // wait through sleep(): a stopped chain ends at once
    return "out";
  },
});

In Python

class SetLamp(Action):
    kind = "set_lamp"
    title = "Set lamp"
    inputs = (Port("in", "flow"), Port("colour", "colour"))

    class Options(BlockOptions):
        colour: str = Field(default="#ff8800", json_schema_extra=ui("colour"))

    async def run(self, inputs):
        self.ctx.lamp = inputs["colour"]
        return "out"

The look

Every style sits under the class ng. Set the --ng-* variables to make it yours: --ng-accent, --ng-surface, --ng-ink and the three fonts. Dark follows the system, or data-theme="dark" on any parent.

The runtime

The same in JavaScript and Python. The JavaScript runtime uses nothing of a page, so it runs in Node.js as well.

JavaScriptPythonWhat it does
defineBlock(spec)subclass Trigger, Action, Loop, ValueBlockA block type
registry(STANDARD, …)the sameBlock types by kind
catalogue(registry)the sameThe block types as the editor wants them
parse(document)the sameA graph from JSON; refuses a malformed one
check(graph, registry, ctx)the same.problems: what is wrong, in words for the user

engine.load(graphs)the sameReplace the graphs
engine.activate(), deactivate()the sameStart listening; stop everything
engine.fire(graphId, nodeId)the sameStart a chain by hand
engine.evaluate(graphId, nodeId, dot)the sameA value without a chain, for graphs that only calculate
engine.status()the sameWhat is loaded, valid, listening and running

What the engine guarantees

  • Nothing runs unless the engine is active. deactivate() stops every chain and calls your release(), where you return to a safe state.
  • A block that fails ends its own chain and is reported. The engine goes on.
  • A graph with a mistake does not run. check() names every mistake.
  • A graph cannot run away: there are limits for time, steps and nesting, and you set them.
new Engine({ context, registry, limits: {
  maxRunS: 3600,      // longest a chain without a loop may run
  maxSteps: 10000,    // steps of one way of a chain
  minRoundS: 0.02,    // shortest round of a loop
  maxLoopDepth: 8,    // loops inside loops
  maxCallDepth: 16,   // graphs running graphs
} });

Other platforms

Noodlegraph has three layers. The specification is shared; editors and runtimes exist per platform and share no code.

LayerTodayTo add a platform
Specification, spec/The graph document, how blocks are described, the rules for checking and running, 34 test graphs
Editors, editors/Web: any browser, or a web view inside a desktop applicationRead and write the graph document; take the block catalogue
Runtimes, runtimes/JavaScript and PythonFollow spec/SPEC.md and pass spec/tests/

Because every runtime passes the same test graphs, a graph drawn in any editor runs the same way everywhere.
